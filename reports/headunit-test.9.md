## How it was built

`adapter/incremental_release.py` took the published test.8 APK (SHA-256 checked against [its release.json](headunit-test.8/release.json)) and applied the `# App updates` section of `patch_headunit.py`. That section changes no smali, so the Spotify backend DEX is byte-identical to test.8. The helper DEX was recompiled from `adapter/src`, and the binary manifest gained `REQUEST_INSTALL_PACKAGES`, the non-exported `local.spotify.unified.UpdateResultReceiver` and versionCode 95486. Resources, the BYD interface and native libraries are byte-identical.

## Implemented in this APK

Spotify updates itself from this project's published test builds; see [adapter/README.md](../adapter/README.md#test9-app-updates) for the design.

- Once a day the backend reads `https://diagnostics.localcharge.app/v1/updates/spotify-android-head-units` and accepts only the server's exact schema-1 record for this project (test.N, versionCode 95477 + N, exact tag and asset URLs).
- A newer build is downloaded into private storage (automatic downloads on Wi-Fi only by default), resumed after interruptions, and verified: size, SHA-256, package, versionCode, minSdk and the pinned release certificate.
- Installation uses a PackageInstaller session that only Android's Update confirmation completes; Spotify offers it once per build when the player opens while music is not playing. Head unit settings → Updates has the switches and buttons.

## Verification

- **152** plain-JVM updater checks pass, including the live test.8 record from the server, every feed field and URL rule, trusted redirect hosts and full/resumed/corrupt/oversized/paused downloads; **39** sign-in checks pass.
- The release audit passed **45/45** checks, including three new `Updates /` checks. See [apk-audit.txt](headunit-test.9/apk-audit.txt). The compatibility audit reports no failures; the only helper-DEX call above API 28 in the updater is `setRequireUserAction`, guarded for Android 12+.
- On AOSP emulators **Android 9 (API 28) and Android 13 (API 33)**, in both the dry run and the publishing run: test.8 was installed and started, test.9 installed over it as an update (versionCode 95486, installer permission declared), the player started, the update job was scheduled, a forced job run fetched the live update feed and reported `up_to_date`, the crash buffer stayed empty and the backend kept running.
- The feed record [spotify-update-test.9.json](headunit-test.9/spotify-update-test.9.json) was generated by `tools/update_record.py` and parses with the app's own `UpdateFeed`.

## Not yet verified

Downloading, verifying and installing a newer build through the app can only be exercised once test.10 is published. The "allow installs from Spotify" setting, the Android Update window and the offer dialog have not been seen on a head unit. test.9 has not been installed in a car; the test.8 sign-in changes are not yet verified in a car either. Real vehicle sleep/reboot, account switching A → B → A, offline downloads, steering-wheel controls, DiLink 5.1 / Android 13 lighting and other head units remain unverified.
